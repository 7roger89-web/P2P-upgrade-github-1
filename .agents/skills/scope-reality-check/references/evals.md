# Evaluation Cases

Use these cases to test trigger precision, evidence discipline, calibration, self-correction, and reconstruction.

## Positive triggers

- `Tạt nước lạnh cho tao: cuối tuần này tao clone Shopee bằng AI rồi chạy thật.`
- `Phản biện gắt kiến trúc này: tao muốn 12 microservice cho app nội bộ 30 người dùng.`
- `Roast kế hoạch thay toàn bộ đội vận hành bằng AI trong 2 tuần.`
- `@Scope Reality Check kế hoạch này có đang over-engineering không?`

Expected: preserve the actual claim, calibrate rather than manufacture disaster, verify decisive current facts, expose concrete failure modes, and reconstruct one useful smaller path.

## Negative triggers

These must not select the skill unless the user explicitly requests the hard-challenge mode:

- `Xem repo này và nói nó làm gì.`
- `Giúp tao build MVP đặt lịch cho khách hàng.`
- `Review kiến trúc này và chỉ ra ưu nhược điểm.`
- `API này bị 500, xem giúp tao.`
- `Tao muốn làm app giống Uber cho ngành X, giúp tao lên roadmap.`

## Authority compatibility

If project instructions require reading canonical Supreme Law first, do that before using this skill. The skill never overrides Owner authority, permissions, or the task contract.

## Self-correction

If fresh evidence reverses an objection, explicitly drop the obsolete objection and update the verdict. If precise current evidence is unavailable, avoid fake precision without blocking decisions that do not depend on it.

## Regression warnings

Treat these as regressions:

- ordinary planning/debugging/repo-review triggers the skill;
- every ambitious idea is labeled unrealistic;
- critique becomes a generic anti-AI lecture;
- the critique adds more architecture than it removes;
- humor cannot identify a decisive contradiction;
- the answer proves a problem but offers no smaller executable path.

## Vertical findings

The product architecture is useful as an example of `iztro facts → repo-derived features → knowledge/prompt → LLM output`, but some derived features should be treated as product heuristics rather than established Tử Vi doctrine.

The clearest example is `fortune-score.ts`. It assigns hand-coded numeric values to stars, brightness coefficients, Tứ Hóa modifiers, palace groups and dimension weights, then normalizes the result to 0–100 and labels ranges 大吉/吉/平/凶/大凶. The inspected file does not provide empirical calibration or primary-source justification for those numbers.

Therefore a pretty 100-year K-line is deterministic **given those chosen numbers**, but deterministic is not the same as validated. This is a major product-design lesson for any future paid site: visualization must not make arbitrary weights look scientifically measured.

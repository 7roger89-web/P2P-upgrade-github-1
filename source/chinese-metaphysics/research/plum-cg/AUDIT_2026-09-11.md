### `shell-quote@1.8.2`

- Advisory: `GHSA-w7jw-789q-3m8p` / `CVE-2026-9277`.
- Dependency path: root devDependency `npm-run-all@4.1.5` → `shell-quote@1.8.2`.
- Package reachability: **BUILD_TOOLCHAIN_REACHABLE** because `npm run build` executes `run-s typecheck bundle`.
- P2P CEGUI production/runtime reachability: **NO**. `run_cegui_capability.mjs` checks the pinned upstream SHA and imports the already-built `dist/index.esm.js`; it does not load `npm-run-all` or `shell-quote`.
- Exploit-path reachability under the current pinned build command: **NOT_REACHED**. The critical advisory requires attacker-influenced object tokens with a malicious `.op` value to reach `shell-quote.quote()`. In `npm-run-all@4.1.5`, the `quote()` calls on the run-s path receive CLI/default argument strings; its separate `parse()` path normalizes parsed tokens to strings and sends argv to `cross-spawn` rather than feeding those objects back into `quote()`.

Verdict: **do not force-upgrade the CEGUI dependency tree for this critical under the current bounded runtime/build path**. Keep it as build-tool security debt and reassess if the build interface changes to accept object-shaped/untrusted programmatic inputs or the upstream pin is refreshed.

### `vitest@3.0.9`

- Advisory: `GHSA-5xrq-8626-4rwp` / `CVE-2026-47429`.
- Dependency path: direct root devDependency `vitest@3.0.9`.
- Package reachability: **TEST_TOOL_REACHABLE** because the audit/test job runs `npx vitest run`.
- P2P CEGUI production/runtime reachability: **NO**. Vitest is not imported by `dist/index.esm.js` or the P2P CEGUI adapter.
- Exploit-path reachability under the current hosted command: **NOT_REACHED**. The advisory requires an exposed Vitest UI/API server or Vitest UI/Browser Mode on Windows. The verified P2P audit uses one-shot `npx vitest run` on Ubuntu with no UI/API/browser mode.

Verdict: **do not mutate the CEGUI runtime dependency path for this critical**. Keep the vulnerable test-tool version visible as development debt; upgrade it in a separately bounded toolchain-refresh slice if/when the upstream pin or testing mode changes.

## Vertical findings

`README_Tutorial.md` gives explicit formulas for origin 策/轨 counts, 三五之数, 错综数 and upper/lower moving-line branches. `src/index.ts` visibly implements the same arithmetic structure. The repo therefore has unusually good traceability from tutorial formula → code → test.

The mapping of digit 5 is not hidden: the repo supports alternative conventions and requires caller context for one mode. That is a strength because disagreement is represented as configuration instead of silently normalized away.

What remains unproven is historical/source fidelity. Unit tests prove that code matches expected vectors, not that those vectors are faithful to an authoritative edition of 皇极梅花/策轨法.

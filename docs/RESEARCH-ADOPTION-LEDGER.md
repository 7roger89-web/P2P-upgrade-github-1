## 1. Purpose and authority

This ledger records, for every researched external source, Owner idea, or internal research direction: what was researched, what was **selected**, what was deliberately **rejected**, how selected ideas translate into provider-neutral P2P capabilities, what has been implemented/shipped/verified, what remains planned/partial/deferred, and where the evidence lives. External research is **provenance, not authority**; P2P adopts ideas selectively, not repositories wholesale. Chat memory is never a source of truth — the standing integration rule is:

> `OWNER_SELECTED_CAPABILITY -> DURABLE_ROADMAP_RECORD`: whenever the Owner accepts a new P2P feature/capability/research direction, P2P must update this ledger (and the roadmap, charter, and capability ledger as applicable) before or during the goal that acts on it.

| Pattern | Rationale |
| --- | --- |
| TASK_AS_AGENT / 174_NUI_FACULTIES_AS_AGENTS / HOSTS_AS_CANONICAL_AGENTS | A task, skill, faculty, or host is never an agent identity; naming never confers capability |
| SECOND_TASK_TRUTH_STORE / SECOND_EXECUTOR / COMPETING_ROUTER | No second runtime truth store, executor, or router competes with canonical state or P2P orchestration |
| UNBOUNDED_SWARM / FULL_CONTEXT_PRELOAD / BLIND_RETRY | Parallelism is bounded and evidence-justified; context is loaded on demand; retries require mutation certainty |
| HOST_OUTPUT_AS_FINAL_EVIDENCE / AI self-report as evidence | Output is proposed until deterministically verified (OUTPUT_NOT_EVIDENCE) |
| AUTO_PROMOTION_AFTER_GOAL_PASS | Goal PASS, candidate verification, release, and promotion are separate states |
| FULL_CHAT_AS_PROJECT_STATE | Project state survives sessions and hosts; transcript is not state |
| PERMISSION bypass / auto-approve-all / dependency-chain autonomy | Composition never widens permission; every escalation needs its own authority and evidence |

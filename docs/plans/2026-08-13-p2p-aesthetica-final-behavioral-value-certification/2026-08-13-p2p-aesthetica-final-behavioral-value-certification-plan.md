## Goal

Certify, from real behavior rather than successful execution alone, whether the installed `p2p_aesthetica` specialist materially improves beginner-relevant UI/UX outcomes over `P2P + p2p-uiux` alone. The certification must preserve the exact canonical eight-agent governance model and must honestly show where Aesthetica is useful, unnecessary, unavailable, or harmful through overhead/overdesign.

## Problem

HC1–HC18 proved real identity and host compatibility for `p2p_aesthetica` in release `8.4.7-C-codex.9`, but that proves execution, not material UI/UX value. The final decision needs a controlled A/B comparison across representative UI types, beginner language, accessibility pressure, design-system discipline, feasibility, cost, negative cases, fallback, and routing boundaries.

The required Phase 0 trust smoke cannot be bypassed: the exact project-local `.codex` configuration must be active in a newly started session before a child thread or A/B behavior is considered valid.

## Scope

- Persistent trust smoke for the exact development project, including project `.codex` activation, agent enablement, Aesthetica discovery, and one bounded real child.
- Six fixed beginner-language scenarios: operations dashboard, mobile customer product, content/interactive experience, ecommerce flow, small cosmetic change, and backend-only request.
- At least one approved Design System scenario and one greenfield/no-Design-System scenario.
- Accessibility pressure, cross-domain UI-performance ambiguity, overdesign, and small-task overhead cases.
- Real A/B outputs, anonymized/blinded review where practical, explicit implementation consequences, quality dimensions, cost/orchestration observations, and routing policy.
- Aesthetica-unavailable fallback, repeated real-thread consistency, beginner benefit, critical-failure checks, and required regressions.
- Durable plan, evidence, benchmark, actual-status, QA, and supervisor reports in the development source.

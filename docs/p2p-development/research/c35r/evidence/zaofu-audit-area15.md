# ZaoFu Audit Area Group 15: Permissions, Security, Secrets, Side-Effects & Budget

This report details the findings for Area Group 15, focusing on the implementation of permissions, security, safety, control actions, cost tracking, and metrics in the ZaoFu codebase.

## 1. Security & Safety

### Security (`src/zf/core/security/`)
**What ZaoFu implements:**
ZaoFu implements a robust attestation and hashing system to ensure the integrity of artifacts and state packets.
- `src/zf/core/security/attestation.py`: Defines `Attestation` and `VerificationResult`. It computes SHA-256 attestations for 6 frozen artifact classes: task contract freeze, State Packet, dispatch context manifest, role instructions briefing, required skills manifest, and research artifact index.
- `src/zf/core/security/hash.py`: Provides unified SHA-256 helpers (`sha256_file`, `sha256_json`, `sha256_text`).
- `src/zf/core/security/nonce.py`: Implements `NonceManager` for managing nonces.
- `src/zf/core/security/signing.py`: Defines `EventSigner` for signing events.

**Key implementation semantics:**
- Attestations are generated by the kernel after a stable artifact is written. Workers cannot mutate the attestation files.
- The system uses a schema-versioned approach ("1.0") for attestations.
- Recovery and dispatch paths can verify attestations to detect tampering.

**Coupling/boundaries:**
- Depends on `zf.core.state.atomic_io` for atomic writes.
- Used by the kernel for freezing and verifying artifacts.

**Maturity signals:**
- Unit tests are present (`tests/test_security_hash.py`, `tests/test_security_nonce.py`, `tests/test_security_signing.py`).

### Safety (`src/zf/core/safety/`)
**What ZaoFu implements:**
ZaoFu includes path safety checks to prevent unauthorized or dangerous file operations.
- `src/zf/core/safety/path_guard.py`: Defines `PathGuardError`, `WorkdirOwnerMarker`, and `PathGuard`.

**Key implementation semantics:**
- `PathGuard.assert_disjoint` checks if source and target roots are disjoint to prevent source mutations during refactoring (r6 write_violation class).
- It checks for `.zf-workdir-owner.json` markers.

**Coupling/boundaries:**
- Used during runtime cleanup and workdir creation.

## 2. Control Actions & Permissions

### Control Actions (`src/zf/runtime/control_actions_*.py`)
**What ZaoFu implements:**
ZaoFu uses a mix-in architecture to define controlled actions that require human approval or operator intervention.
- `src/zf/runtime/control_actions_plan.py`: `PlanApprovalActionsMixin` handles `plan-approve` and `plan-reject` actions. The agent only recommends; the human (actor is always "operator") clicks to approve or reject.
- `src/zf/runtime/control_actions_workflow_request.py`: `WorkflowRequestActionsMixin` handles workflow requests.
- `src/zf/runtime/control_actions_emit.py`: `ActionEmitMixin` handles emitting actions.

**Key implementation semantics:**
- Token-gated approve/reject from Web/kanban-agent surfaces.
- Events land in `events.jsonl`. The kernel wake re-enters incubation (approved) or feeds synth replan (rejected).
- `plan-reject` requires a reason (feedback for synth replan).

**Coupling/boundaries:**
- Depends on `zf.core.events.model.ZfEvent`.
- Integrates with the Web/kanban-agent UI for operator interaction.

**Maturity signals:**
- Unit tests are present (`tests/test_control_actions_plan.py`, `tests/test_control_actions_recovery.py`, etc.).

## 3. Cost, Budget & Metrics

### Cost Tracking (`src/zf/core/cost/`)
**What ZaoFu implements:**
ZaoFu tracks token usage and enforces budgets.
- `src/zf/core/cost/tracker.py`: Defines `CostSummary` and `CostTracker`. Uses an active+archive layout (today's records in `.zf/cost.jsonl`, previous days rotated).
- `src/zf/core/cost/billing.py`: Defines `BillingAdapter` and specific adapters like `OpenAIBillingAdapter` and `AnthropicBillingAdapter`.
- `src/zf/core/cost/catalog.py`: Defines `PricingCatalog` and `RateResolution` for resolving model rates.

**Key implementation semantics:**
- Records token usage (input/output) and calculates USD cost based on pricing catalogs.
- Checks budget limits (`check_budget`).

**Coupling/boundaries:**
- Used by the autoresearch loop (`src/zf/autoresearch/loop_driver.py`) to stop execution if `budget_exhausted` (`cost_usd_so_far >= cfg.budget_usd`).

**Maturity signals:**
- Extensive unit tests (`tests/test_cost_tracker.py`, `tests/test_cost_budget_enforcement.py`, etc.).

### Metrics (`src/zf/runtime/`)
**What ZaoFu implements:**
ZaoFu gathers metrics on briefings and automation performance.
- `src/zf/runtime/briefing_metrics.py`: Observes rendered briefing size (bytes, estimated tokens, line count) without making it a workflow gate. Uses soft budgets (`_SOFT_BUDGETS`).
- `src/zf/runtime/automation_metrics.py`: Aggregates signals (autonomy, reliability, governance) from event types.

**Key implementation semantics:**
- Tracks human-touch events (escalations, owner decisions) to measure autonomy.
- Tracks reliability incidents (safe_halt, circuit_tripped).
- Tracks governance/drifting (scope_violation, permission_drift).

**Coupling/boundaries:**
- Depends on `zf.core.events.model.ZfEvent`.

**Maturity signals:**
- Unit tests present.

## 4. Provider Neutrality

The audited areas are **provider-neutral** for the most part. The core security, safety, and control action logic does not depend on specific LLM providers. The cost tracking system (`src/zf/core/cost/billing.py`) uses an adapter pattern (`BillingAdapter`) with specific implementations for OpenAI and Anthropic, making it provider-neutral in design but with provider-specific extensions.

## 5. Summary

ZaoFu implements a comprehensive security and safety framework using SHA-256 attestations for 6 frozen artifact classes (`src/zf/core/security/attestation.py`) and path guards to prevent disjoint source/target mutations (`src/zf/core/safety/path_guard.py`). Permissions are managed through a mix-in architecture for control actions (`src/zf/runtime/control_actions_*.py`), where human operators must explicitly approve or reject plans (`plan-approve`, `plan-reject`), ensuring the agent only recommends while the human clicks. Cost tracking is robust, utilizing an active+archive layout (`src/zf/core/cost/tracker.py`) and a pluggable billing adapter system (`OpenAIBillingAdapter`, `AnthropicBillingAdapter`) to enforce strict budgets (`budget_exhausted` halts execution). The system also tracks autonomy, reliability, and governance metrics (`src/zf/runtime/automation_metrics.py`) based on emitted events. The architecture is largely provider-neutral, with provider-specific logic abstracted behind adapter interfaces in the billing module.

# Bootstrap & Projection Guidance

Status: APPROVED FOR USE
Date: 2026-08-29
Generated by: P2P-GAME-UI-CAP-01

## Purpose

Guidance for new projects to discover and activate capabilities from the UI/Game/Three.js capability catalog based on their project profile.

## Bootstrap Flow

```
NEW_PROJECT
  → IDENTIFY_PROJECT_PROFILE
    → RESOLVE_REQUIRED_CAPABILITIES
      → RESOLVE_OPTIONAL_CAPABILITIES
        → IDENTIFY_GATED_CAPABILITIES
          → EXCLUDE_INAPPLICABLE_CAPABILITIES
            → COMPUTE_PROJECTED_BUNDLE
              → DISCOVER_RELEVANT_PROTOCOLS
                → DISCOVER_ACTIVATED_THIRD_PARTY_CAPABILITIES
```

## Step 1: Identify Project Profile

Classify the project into one of:

| Profile | When |
|---|---|
| `WEB_APP` | Standard web application (React, Vue, Next.js, etc.) |
| `MOBILE_APP` | Mobile application (React Native, Flutter, native) |
| `2D_GAME` | 2D game (canvas, sprite-based, Godot-like) |
| `THREEJS_GAME` | Vanilla Three.js game/experience (no React) |
| `R3F_GAME` | React Three Fiber game/experience |

## Step 2: Resolve Required Capabilities

From `project-profile-routing.json`, extract the `required_capabilities` for the profile. These are always activated.

## Step 3: Resolve Optional Capabilities

From `project-profile-routing.json`, extract the `optional_capabilities` for the profile. Activate only when the project's actual needs justify them.

**Key principle: Do not activate all optional capabilities by default.**

## Step 4: Identify Gated Capabilities

Gated capabilities (`gated_capabilities`) require explicit approval:

- `LICENSE_GATED` — Requires legal/license compatibility review.
- `SECURITY_GATED` — Requires security model review (e.g., MCP permissions).

These cannot be activated automatically.

## Step 5: Exclude Inapplicable Capabilities

Capabilities listed in `excluded_capabilities` for the profile are never activated.

**Key invariants:**
- `WEB_APP` does not receive game capabilities by default.
- `THREEJS_GAME` does not automatically receive R3F-only capabilities.
- `2D_GAME` does not receive Three.js/R3F capabilities unless the project uses them.

## Step 6: Compute Projected Bundle

The projected bundle is the set of activated capabilities for this project:

```
PROJECTED_BUNDLE = REQUIRED ∪ (OPTIONAL ∩ JUSTIFIED) - EXCLUDED - GATED(until_approved)
```

## Step 7: Discover Relevant Protocols

Based on the project profile, provide references to:

| Profile | Protocols |
|---|---|
| `WEB_APP` | UI Design Protocol |
| `MOBILE_APP` | UI Design Protocol |
| `2D_GAME` | UI Design Protocol, Game UI Protocol |
| `THREEJS_GAME` | UI Design Protocol, Game UI Protocol, Three.js Visual Protocol |
| `R3F_GAME` | UI Design Protocol, Game UI Protocol, Three.js Visual Protocol |

## Step 8: Discover Activated Third-Party Capabilities

For each capability in the projected bundle, reference the exact catalog entry from `capability-catalog.json`:

- Exact upstream source and pinned version/SHA.
- License (verified).
- Activation conditions.
- Security notes.

## Project Profile Decision Tree

```
Does the project render a 3D scene?
  NO:
    Is it a mobile app?
      YES → MOBILE_APP
      NO → WEB_APP
  YES:
    Does it use React?
      NO → THREEJS_GAME
      YES → R3F_GAME

Is it a 2D game?
  YES → 2D_GAME
```

## Example Projections

### Example 1: Three.js Voxel Game

```
Profile: THREEJS_GAME
Required: game.three.visual, game.three.asset, ui.game_hud
Optional activated: game.three.spatial_query (for block picking),
                    game.three.adaptive_quality (for mobile support)
Optional NOT activated: game.three.cinematic, game.three.navigation
Gated: none
Excluded: ui.spatial
```

### Example 2: R3F Multiplayer Game

```
Profile: R3F_GAME
Required: game.three.visual, game.three.asset, ui.game_hud
Optional activated: game.three.navigation (NPC pathfinding),
                    game.three.spatial_query (raycasting),
                    ui.spatial (world-space chat bubbles)
Optional NOT activated: game.three.cinematic
Gated: ui.penpot_bridge (if Penpot design workflow needed)
Excluded: none
```

### Example 3: SaaS Web Application

```
Profile: WEB_APP
Required: ui.design, ui.frontend
Optional activated: ui.design_system (shadcn-ui),
                    ui.motion (transitions),
                    ui.component_lab (storybook)
Optional NOT activated: ui.figma_bridge, ui.penpot_bridge
Gated: none
Excluded: all game.* and game.three.* capabilities
```

## Persistence

When a project is bootstrapped, persist:

1. The resolved project profile.
2. The projected bundle (activated capabilities with exact provenance).
3. References to relevant protocols.
4. Any gated capability approval records.

These are persisted in the project's `.p2p/context/` directory following the existing ProjectContextModel schema.

## Anti-Patterns

- Activating all capabilities "just in case."
- Activating R3F capabilities for a vanilla Three.js project.
- Activating game capabilities for a SaaS web app.
- Skipping the license gate for AGPL-licensed Studio components.
- Treating the capability catalog as an install manifest.
